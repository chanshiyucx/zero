# 全站动效设计指南

本文是整站动效的设计标准。新增页面、组件或调整动效时，以本文为准；数值和实现如有变更，需同步更新本文。

## 1. 一条规则，一个例外，一个连续

网站的气质是安静的衬线排版、大量留白和柔和的配色。动效应当像翻阅一本书：翻开一页，内容从容地铺开；翻回刚才那页，它就在原处等着。

整站的动效只有三句话：

1. **进入一个页面，第一屏按块依次浮现。** 点链接、刷新、直接访问、带锚点打开，都是进入。首页的签名书写也是这次入场的一部分。
2. **回去的地方保持原样。** 通过返回链接或浏览器后退 / 前进回到一个页面时，内容直接就位，只有整页短淡入。
3. **同一篇内容保持连续。** 列表和文章之间，标题作为共享元素在两页之间飞行，说明"这是同一篇"。

一致性的标准是：**同样的操作，得到同样的动效。** 动效只取决于读者此刻做了什么，不取决于读者之前看过什么。浏览历史、路由缓存、滚动位置都是读者看不见的状态，用它们决定动效，在读者眼里就是时有时无。

边角情况不另立规则，而是由同一个机制吸收：**延迟封顶。** 序列走到上限后，余下的块一起出现，因此：

- 第一屏以下的块在屏幕外一起播完，读者看不到。
- 刷新后停在页面中段、带锚点打开时，可见内容一起淡入，上下没有断层。

其余原则：

- **一次只有一个视觉主角。** 主角可以是飞行的标题、首页的签名，或展开的第一屏。其余动作必须足够安静，比如整页淡入可以和标题飞行同时发生。
- **每个动作都要有含义。** 动效用来表达"进入""回去""同一篇"，不做装饰。说不出含义的动作就不加。
- **尊重「减少动态效果」。** 系统开启该设置时，入场、签名书写、路由过渡和平滑滚动全部关闭，内容直接呈现。

## 2. 动效 Token

所有时长、曲线、位移都来自同一组 token，定义在 `styles/theme.css` 的 `:root` 中。组件和样式不得写死这些数值。

| Token                      | 值                           | 用途                                                |
| -------------------------- | ---------------------------- | --------------------------------------------------- |
| `--motion-ease`            | `cubic-bezier(0.2, 0, 0, 1)` | 入场与标题飞行的统一曲线：起步快、收尾稳            |
| `--motion-fade`            | `200ms`                      | 站内跳转时新页面的整页淡入                          |
| `--motion-morph`           | `400ms`                      | 共享标题在列表与文章之间的飞行                      |
| `--motion-enter`           | `600ms`                      | 单个内容块的入场时长                                |
| `--motion-enter-distance`  | `8px`                        | 入场时内容块上移的距离                              |
| `--motion-enter-step`      | `90ms`                       | 相邻内容块的错开间隔                                |
| `--motion-enter-max-delay` | `450ms`                      | 延迟上限：序列最多错开五步，之后的块一起出现        |
| `--motion-draw`            | `2s`                         | 首页签名的书写，各笔画按 `--motion-enter-step` 错开 |

三个时长 200 / 400 / 600ms 构成一个节奏家族：淡入最短，飞行居中，入场最长但幅度最小。一次完整的入场约 1s 结束（最大延迟 450ms + 单块 600ms），足够看清"依次出现"，又不至于在每次进入时显得拖沓。签名是首页的主角，允许更从容：约 2.4s 写完，曲线用 `ease-in-out`，像笔尖起落。

全站只有一种节奏。首页块最多，节奏按首页调校；其他页面第一屏只有三到五块，同样适用。调整时以肉眼观感为准，并确认反复进入同一页时不觉得烦。

## 3. 场景

| 场景                       | 动效                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| 进入首页                   | 签名书写一次后停住；简介、近况和各内容分区依次浮现               |
| 进入列表、项目、友链、随想 | 按语义块依次浮现；链接列表以年份为一块，不逐条排队               |
| 列表 → 文章                | 标题飞到文章标题位置，同时新页面淡入；信息行、正文和目录依次浮现 |
| 文章 → 列表（返回链接）    | 标题飞回列表中的原位，列表直接就位                               |
| 返回链接回到其他上一级     | 直接就位，只有整页淡入                                           |
| 浏览器后退 / 前进          | 直接就位，不经过路由过渡                                         |
| 目标标题不在视口内         | 不飞行，其余不变                                                 |
| 刷新、直接访问、锚点打开   | 与进入相同；不在页首时，可见内容在延迟上限处一起淡入             |
| 切换主题                   | 保持现有的整屏擦除过渡，与路由过渡互不影响                       |
| 减少动态效果               | 全部关闭                                                         |

两点推论，不需要额外规则：

- **标题的落点总是就位。** 标题飞回列表只发生在返回时，而返回总是就位，所以标题落地不会和所在行的入场叠加。新增让标题飞进列表的入口时，必须同样标记为返回。
- **框架保持静止。** 导航、返回链接、页脚、顶部渐隐遮罩没有入场。路由过渡时旧画面不动、新画面整体淡入，框架在两页的像素相同，叠加淡入看不出变化，因此不需要单独过渡。

## 4. 构件与用法

### 4.1 入场序列

入场只在 `PageLayout` 的 `<main>`（带 `slide-container`）内生效，用以下属性声明：

| 属性                   | 含义                                                |
| ---------------------- | --------------------------------------------------- |
| `data-slide`           | 该元素自身作为一个入场块                            |
| `data-slide-auto`      | 该元素的每个直接子元素各为一个入场块，按顺序错开    |
| `data-slide-start="n"` | 序列从第 `n` 步开始，用来把几个序列串成一条阅读顺序 |

- **按语义块组织。** 一个块应当是读者会作为整体阅读的单元：一段简介、一个分区、一年的文章、一张卡片、一个段落。不要让每个链接或每行文字单独排队。
- **不要提高延迟上限。** 上限就是"第一屏"的定义。为了让长列表"完整播完"而提高它，会让下方内容和刷新后的可见内容等待更久。
- **共享标题本身不加入场。** 文章的 h1 是飞行的落点，给它加入场会让新快照截到透明的标题。
- **组件里不判断"回来"。** 返回时的入场由 `PageLayout` 统一结束。

### 4.2 站内链接

站内跳转统一走路由过渡，以获得一致的整页淡入：

| 组件                             | 用途                                                   |
| -------------------------------- | ------------------------------------------------------ |
| `TransitionLink`                 | 普通站内链接：进入目标页                               |
| `TransitionLink` + `isReturn`    | 回到读者来的地方，目标页直接就位（返回链接）           |
| `TransitionLink` + `sharedTitle` | 让本页 slug 匹配的标题飞到目标页（返回链接回到列表时） |
| `ArticleTitleTransitionLink`     | 列表中的文章标题：自身就是共享标题，并发起飞行         |

- 参与飞行的标题用 `data-title-transition={slug}` 标记（文章 h1、列表中的标题链接）。
- 外部链接、新标签页打开的链接、页内锚点用普通 `<a>`，不走路由过渡。
- `TransitionLink` 总是以 push 方式跳转并回到页首，因此不接受 `replace`、`scroll`。

### 4.3 新的入场动画

除了内容块和签名，如果某个元素需要自己的入场：

- 关键帧以 `enter-` 开头命名（现有的是 `enter-slide`、`enter-signature`）。返回时，`finishEntrance` 按这个前缀找到并结束它。
- 动画必须是有限次的，且最终帧等于元素的静态样式。这样结束动画、减少动态效果、不支持动画时，看到的都是同一个完成状态。

## 5. 实现

| 位置                                              | 职责                                                                    |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| `styles/theme.css`                                | 动效 token、`enter-slide` / `enter-signature` / `route-fade-in` 关键帧  |
| `styles/utilities.css`                            | `slide-container`：入场序列的错开与延迟上限；`logo-signature`：签名书写 |
| `styles/base.css`                                 | 路由过渡时新页面的淡入、共享标题 group 的时长与曲线                     |
| `lib/utils/dom.ts`                                | `transitionViewIfSupported`、`finishEntrance`、`isInViewport`           |
| `components/page/page-main.tsx`                   | 返回时在绘制前结束整页入场                                              |
| `app/provider/route-view-transition-provider.tsx` | 路由过渡、共享标题命名、连续点击的改向，记录最近一次跳转是否为返回      |
| `components/transition-link`                      | 统一的站内跳转入口                                                      |

关键做法：

- **进入不需要代码。** 新挂载的页面自然播放 CSS 入场；被路由缓存保留的页面再次显示时，浏览器也会重新开始它的 CSS 动画。代码只负责一件事：返回时让它停下。
- **返回在跳转时记录，在显示时读取。** `navigate` 每次都按 `isReturn` 覆盖这个标记，`popstate` 把它置为返回。`PageMain` 在页面挂载或被重新显示时，于 `useLayoutEffect` 中读取它：早于绘制，也早于路由过渡截取新页面。标记只读不消费，所以 React 开发模式下重复执行的 Effect 得到同样的结果。
- **用 Web Animations API 结束入场，不在 DOM 上留标记。** 每次显示都重新判断，不会残留状态。
- **签名书写是纯 CSS。** 每条路径设 `pathLength={1}`，描边长度统一为 1，不需要用脚本测量，服务端渲染的第一帧就是正确的起点。
- **路由缓存会把离开的页面隐藏在 DOM 中。** 查询共享标题时用 `checkVisibility()` 排除隐藏页面，用视口判断决定是否飞行。

## 6. 检查清单

新增页面或组件时：

- [ ] 页面使用 `PageLayout`，内容放在它的 `<main>` 里。
- [ ] 入场块按语义划分，用 `data-slide` / `data-slide-auto` 声明；需要衔接时用 `data-slide-start` 排顺序。
- [ ] 没有写死时长、曲线或位移，全部使用动效 token。
- [ ] 站内链接使用 `TransitionLink`，回到上一处的链接加 `isReturn`。
- [ ] 新的入场动画以 `enter-` 命名，有限次，最终帧等于静态样式。
- [ ] 导航、页脚等框架元素没有入场。

## 7. 禁止事项

- 不要依据浏览历史、路由缓存或滚动位置决定是否播放入场，只看这次跳转是不是返回。
- 不要为边角情况增加新规则。先问延迟封顶能不能吸收它，再问读者是否真的会看到。
- 不要让同一时刻出现两个视觉主角，例如标题飞行时还有整列表级联。
- 不要用 DOM 标记（属性、类名）关闭某个元素的入场：页面被缓存复用时标记会残留。
- 不要做无限循环的装饰动画：持续的运动会和阅读争夺注意力，也无法在返回时结束。
- 不要给共享标题自身加入场或透明度变化。
- 不要每帧重复发起平滑滚动或写入未变化的 DOM。

## 8. 验证

- 首页 → 随想 → 返回首页 → 再进入随想：两次进入随想的动效完全一样；回到首页时签名直接是写好的样子。
- 列表 → 文章 → 返回链接：标题往返飞行；返回时列表直接就位，没有闪烁。
- 浏览器后退 / 前进：直接就位。
- 首页滚动到底部后刷新：可见内容一起淡入，没有断层。
- 手机尺寸、目标标题在屏幕外时返回：不飞行，列表同样直接就位。
- 连续快速点击两篇文章：最终进入第二篇，没有错误的标题淡出，控制台没有未处理的异常。
- 开启「减少动态效果」：没有任何入场、签名书写、过渡和平滑滚动。

## 9. 已知限制与后续

- **返回链接是 push 而不是真正的后退。** 返回列表时页面回到顶部，长列表里的目标标题常在视口外。后续可以在上一条站内历史正好是返回目标时改用 `router.back()`，恢复滚动位置，让标题飞回读者离开时的位置。
- **浏览器后退 / 前进不经过 View Transition。** 历史导航期待的是"恢复"，直接就位是有意为之。
- **错开依赖 `sibling-index()` 与带类型的 `attr()`。** 目前只有 Chromium 支持，其他浏览器中所有块同时淡入、签名各笔画同时书写，属于可接受的降级。
